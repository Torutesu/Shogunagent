# Migration from ShogunAI

Source: `Torutesu/ShogunAI-` at the commit recorded in `docs/shogunai-origin/SOURCE.txt`. Files were copied, not moved with history; the source repository remains the history of record for everything under `crates/` and `apps/api/` up to that commit.

## What was migrated and why

| Path | Status | Reason |
|---|---|---|
| `crates/shogun-agents` | migrated as is | Dependency-free. L1/L2/L3 vocabulary, `ApprovalQueue`, `SendAction` (L3 by type), entitlement. Core of the permission pillar. |
| `crates/shogun-fusion` | migrated as is | Confidence bands, half-life decay, context assembly and budget. Depends only on `shogun-agents`. |
| `crates/shogun-redact` | migrated as is | Dependency-free secret masking used on every DB write and log path. |
| `crates/shogun-license` | migrated as is | Ed25519 token verification reused for the ShogunAI sync path. `hardware_device_id` is macOS-gated and unused here. |
| `crates/shogun-memory` | migrated as is | Schema V1–V91 (frozen), event log, state tables with provenance, loops consolidator, entity pages, federated search, sanitize, traceability, import. Capture-specific tables remain but stay empty in hosted mode. E24: feature `embed-local` (default off; on in the server build profile) drives the ONNX embedder from a `ModelSpec` (default `nomic-embed-text-v1.5`, Apache-2.0, 384-wide Matryoshka prefix); V102 records the model of every vector row and the store's active space, and search never ranks vectors of two models together. E43: `multilingual-e5-small` (MIT, 384 native, `query:`/`passage:`) is a full opt-in spec with its own cutoff (0.63); its pins are placeholders until the operator records them, and switching a store to it re-embeds in place (`docs/embedding-model-setup.md`). |
| `crates/shogun-mcp` | migrated, feature `desktop` added (E1-T7, default off) | `MemoryBackend`, `ApiLevel`/`tool_level`/`tool_group`, toolsets, source policy, rate limit, REST routing, MCP server, approval store. Behind `desktop`: the Mac app's data folder (`desktop_paths`, the `~/Library/Application Support` lookup `plan_source::app_data_dir` used to do inline) and the owner-only socket to the app's live form review (`forms_api::{request, same_uid}`; the server answers `form_unavailable`). Kept in the default build on purpose: `memory_api_settings` and `live_tokens` are the token-list format and live re-check every face uses (`TokenRegistry` is built from them); `plan_source` / `trial_relay` are the file-backed plan source behind `PlanLock`, `account.status` and every `*_api` settings path; `launcher_check` is the pure policy table the token listing names per connection (reading signatures is `shogun_core::desktop::launcher`); `client_install` feeds `client_config`'s REST preview and the doc-sync tests; `chat_bridge` serves `llm::delegate_tools`. None of them contains a `cfg(target_os = "macos")`. The Tool enum, its wire names and REST paths are untouched (E4 owns the tool table). |
| `crates/shogun-integrations` | migrated as is | Connector scope table (`scope.rs`: deny what is not in the table, ExternalSend is always L3), connection FSM, OAuth. Since E5-T5 credentials go through the `token_store::TokenStore` trait (principal × slot, values in `Secret`): `FileSealedTokenStore` (ChaCha20-Poly1305, key HKDF-derived from the principal's store key, files 0600) on a local server, the interface-only `RemoteTokenStore` (KMS envelope over database rows; unused by the hosted service, whose sidecar keeps grants in the file-sealed store under each principal's key and serves them to the gateway since E50, `hosted_connect`), and the Keychain behind the crate's `desktop` feature (`keychain`, `keychain_store`, `code_signature`, the `open` browser launcher). `PrincipalGrants` adapts any store to the per-service `GrantStore` the refresh path uses. |
| `crates/shogun-microphone` | migrated as a dependency, desktop-only since E25 | Optional dependency of `shogun-mcp` and `shogun-core`, pulled in only by their `desktop` feature (E25): the default server graph does not contain it, and the server answers a named microphone selection as unavailable. Its own `desktop` feature compiles the CPAL discovery (`platform.rs`), so the crate carries no default-compiled `cfg(target_os = "macos")` site. |
| `crates/shogun-core` | migrated, feature `desktop` added (E1-T7, default off) | Platform-neutral parts (dreamcycle, llm, ai_search, context, daemon/*, db_backend, metrics, `shogun_api` and `shogun_mcp` binaries) are the server and build by default. Behind `desktop` (`lib.rs`): `audio/*`, `notch/*`, `forms.rs` + `forms/*`, `inline`, `paste_verification`, `gmail_direct`, `gmail_local`, `mail_actions`, `model_asset`, `known_links`, `left_option_hold`, `panel_events`, `release_notes`, `self_install`, `sound`, `auto_update`, `plan_mirrors`; in `capture/*` the walk and pipeline (`walk_policy`, `noise`, `secret_field`, `pipeline`, `focus_watch`, `wake`, `accessibility_gate`) and the Vision OCR + cross-process file lock (`capture/visual_recall/desktop.rs`); in `meeting/*` the live lane (`statemachine`, `endwatch`, `gate`, `system_audio`, `audio_health`, `live_summary`, `live_translation`, `transcript_writer`, `keyterms`, `settings_store`); and the new `desktop/{keychain,tokens,launcher}` glue, which holds every Keychain read the daemons made inline in `db_backend`, `daemon/db`, `settings_seal` and the two binaries (the binaries take `SHOGUN_API_TOKEN` when the feature is off). `daemon/briefs` keeps libc under `desktop` and uses Chrono in the server to match SQLite's host-local calendar (UTC on UTC hosts), including a day whose midnight falls in a DST gap (it starts at the first valid instant after the gap); principal-specific timezones are not implemented. The server's dream cycle (`dreamcycle/jobs`, the hourly `tenancy/dream_tick` cycle ids) uses the same host offset; on a non-UTC host, the first day after upgrading from a release that labelled hourly cycles in UTC can find an hour's id already in the ledger and skip that hour once — the material is consolidated by the next hour's cycle, not lost. Kept in the default build because the data layer and its Memory API tools use them: capture policy (`capture::{exclusion, control, status, visual_recall, dedup, own_app}`), stored meeting notes (`meeting::{minutes, export, recap, templates, talk_share, anchors, reminders, settings, detect}`), `translate*`, `reply_draft`, `voice_dictionary`, `dictionary_learn`, `rewrite_*`, `writing_recipient`, `screen_context`, `inline_context`, `model_catalog`, `gmail_shape`, `mail_batch`. `audio` implies `desktop`. The feature compiles on Linux (`check-feature-matrix.sh`); `scripts/check-desktop-gate.py` fails the build if a default-compiled file gains a `cfg(target_os = "macos")`. |
| `crates/shogun-cli` | migrated as is | The `shogun` command. Renamed to `shogunagent` in E10-T10. `shogun models list|path|fetch|verify` (E24) manages the local embedding model; `fetch` is the only download of one and needs the `embed-local` feature; it refuses a model whose pins are placeholders (E43). |
| `crates/memory-bench`, `pii-bench`, `dedup-bench`, `extract-eval`, `fusion-eval` | migrated as is | The eval harnesses that back the same-harness benchmark publication. |
| `crates/spike-harness` | migrated as a dependency | `memory-bench` depends on it. |
| `apps/api` | migrated as is | Hono relay on Cloudflare Workers + Postgres: Ed25519 auth, reserve-then-settle metering, zero-retention logging, schema enforcement, `/v1/review`. Becomes the gateway (agent auth, wallet, 402, router control plane). The `gmail:setup` / `google:setup` Swift scripts are macOS developer tools and will be removed with the desktop OAuth flow. |
| `packages/config` | migrated | Holds the license public key that `shogun-license` tests include. |
| `scripts/check-*.py`, `check-feature-matrix.sh`, `cargo-audit.py`, `check-cargo-audit.py`, `ci-postgres*.sh` | migrated, desktop references removed | The invariant guards and the feature-matrix runner. |

| `docs/memory-api-mcp.md`, `docs/examples/` | migrated at the same paths | The Memory API spec and the generated client-config examples. `shogun-mcp` doc-sync tests read them (`client_config.rs`), so the paths are kept. |
| `apps/docs/memory-api/*.mdx` | migrated, pages only | The four public Memory API pages (overview, mcp, rest, cli). `shogun-mcp/tests/docs_tool_counts.rs` and `client_config.rs` check them against the tool table. The rest of the Mintlify site is not carried over. |
| `docs/shogunai-origin/` | migrated as reference | Requirements v1.0, relay and gateway design, context architecture, continual learning, unit economics, memory quality verification, embedding setup, connector plan, search eval, positioning, and the ShogunAI `CLAUDE.md`. Read-only reference; ShogunAgent decisions live in `README.md` and `docs/implementation-plan.md`. |

## Changes made during migration

- Root `Cargo.toml`: workspace members reduced to the crates above; lints and profiles unchanged; license set to Apache-2.0 for the OSS release.
- `Cargo.lock`: pruned of the desktop-only dependency tree (307 packages removed, none added).
- `crates/shogun-core/src/audio/cue_cancel.rs`: the test fixture `voice-start.wav` is copied to `src/audio/fixtures/` instead of being included from `apps/desktop`.
- `scripts/check-feature-matrix.sh`: the `--exclude shogun-desktop-spike` flags and the desktop shared-enum grep are removed. E1-T7 added `-p shogun-core --features desktop,daemon-server` and `-p shogun-mcp --features desktop,server` clippy runs and the `check-desktop-gate.py` guard.
- E1-T7 (`desktop` feature): `shogun-core/src/desktop/`, `shogun-core/src/capture/visual_recall/desktop.rs`, `shogun-mcp/src/desktop_paths.rs` and `shogun-mcp/src/forms_api/peer.rs` are new files holding code moved verbatim out of the modules that stay in the default build; nothing was deleted. `shogun-cli` enables `shogun-mcp/desktop` for macOS targets only, so the `shogun` command on a Mac still finds the app's `memory.db`. The examples `audio_probe`, `inline_bench` and `rewrite_ab` have `required-features = ["desktop"]`; the tests `hover_to_state`, `meeting_lifecycle` and `hosted_speech_live` are `#![cfg(feature = "desktop")]`, and `api_startup` / `mcp_startup` run when it is off (they set `SHOGUN_API_TOKEN`).
- E24: `shogun-core/src/model_asset.rs` (the pinned, SHA-256-checked static download) moves from `desktop`+`net` to `net` alone: it has no Mac code, and `shogun models fetch` uses it for the embedding model.
- `crates/pii-bench/src/corpus.rs`: the synthetic Stripe-shaped fixture is assembled with `concat!` so GitHub push protection does not read it as a live key. The bench input is unchanged.
- `package.json`, `pnpm-workspace.yaml`, `turbo.json`: reduced to `apps/*` and `packages/*`.

## Keeping in step with ShogunAI

Until the Mac app depends on ShogunAgent crates directly, changes to shared crates land in ShogunAI first and are ported here, or vice versa, by hand. The `wire-freeze` snapshot test (E4-T3) and the shared tool table (E14-T1) are the two places where drift would show.
